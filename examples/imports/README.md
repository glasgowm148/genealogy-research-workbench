# Fictional upload examples

All people, places and records are invented. The living example demonstrates exclusion, and is not a real person.

`fictional-family.ged` uses Unicode GEDCOM 7 syntax, shared/inline notes, continued text, event-level source citations, supplied coordinates, a marriage, occupation and a restricted living person. The same record/tag layout is accepted from GEDCOM 5.5/5.5.1 exports in any declared UTF-8, UTF-16, ANSI, ANSEL, ASCII or Mac encoding; `tests/test_import_variations.py` generates fictional variants of each. Dates remain supplied strings, including ranges and uncertainty; coordinates are validated, never geocoded. No network requests occur.

`fictional-onetree.json` uses `{ "data": { "provider-id": profile } }`. The importer also accepts a plain profile dictionary, a profile list, single rows, or `{ "people": [...], "relationships": [...] }`. Names, common birth/death fields, sex assertions, biographies, aliases, supplied birth/death coordinates, father/mother, spouses and children are mapped. Provider `Name`/`profile_id` retains the established external identity contract; numeric IDs remain aliases for relationship resolution. Generic lowercase `name` is display text, and explicit `id` values identify those people. Relationships point from child to parent. Missing relatives are omitted with warnings, never invented. Provider confidence remains unassessed; a provider's `documented` label is retained in import metadata and mapped to neutral `unknown` confidence.

Imports default to private. Explicit provider privacy/access fields remain effective; legacy `Privacy >= 50` retains its public access mapping, while living/unknown status still prevents default public export. GEDCOM `RESN` blocks publication eligibility. Sources and citations never make an imported assertion independently documented. OneTree source/citation schemas, arbitrary custom GEDCOM tags, media attachments and GEDZIP are not interpreted; unsupported GEDCOM structures are counted in the import report. Original observations remain transient adapter records; portable cases retain safe import metadata and normalized entities, not the full original file. Raw genetic payloads are rejected.
